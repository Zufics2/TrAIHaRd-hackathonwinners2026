## B. Участник №3 — реальные наблюдения (Gemini)

**Файл:** `data/templates/prefilled_P3_gemini_baseline_v1.csv` — уже заполнены ID, запросы, провайдер и путь скриншота. Откройте его в Google Sheets (Файл → Импорт → Загрузить) и заполните **только** пустые столбцы:

| Столбец | Что вписать |
|---|---|
| `timestamp` | время получения ответа: `2026-11-20T14:12+05:00` (с `+05:00`!) |
| `model` | если Gemini показывает модель, иначе пусто |
| `region_setting` | `Алматы, без VPN, аккаунт без истории` — как есть |
| `answer_text` | **весь** ответ: выделить → копировать → вставить в ячейку. Не сокращать, не исправлять |
| `cited_urls` | все ссылки-источники: правый клик по источнику → «Копировать адрес ссылки». Разделитель ` \| `. Нет ссылок — оставить пусто |
| `notes` | что-то необычное (ответ без источников, отказ, ошибка) |

**Правила сбора**
1. Новый чат на каждый запрос. Не продолжать предыдущий диалог.
2. Запрос вставить дословно из таблицы (копированием).
3. Ничего не уточнять у модели. Первый ответ — это и есть наблюдение.
4. Ссылки: полный адрес `https://...`. Не текст «svet.kz», не обрезанное `https://svet.kz/kat…`, не markdown `[1](...)`. Параметры вроде `?utm_source=...` оставлять — система сама их обработает.
5. **Скриншот:** весь ответ вместе с источниками (если не помещается — несколько: `OBS-P3-G01.png`, `OBS-P3-G01_2.png`). Имя строго `<response_id>.png`. Не должно быть видно личных данных: имени аккаунта, почты, истории чатов — закройте боковую панель.
6. Если появилась share-ссылка на диалог, её можно вписать в `evidence_link` вместо пути к скриншоту.

**`verified_by` — проверка чужих строк.** Вы проверяете строки **P2**, P2 — ваши. Для каждой строки:
- текст в `answer_text` совпадает со скриншотом;
- все ссылки открываются и совпадают с источниками на скриншоте;
- запрос тот же.

Всё совпало → `verification_status=verified`, `verified_by=P3`. Не совпало → `rejected` и причина в `notes`. Свои строки себе не проверяйте.

## A. Участник №2 — research + наблюдения (ChatGPT Search)

**1. Наблюдения:** `data/templates/prefilled_P2_chatgpt_search_baseline_v1.csv` — те же правила, что у P3. В ChatGPT поиск должен быть **включён** (значок Search или источники в ответе). Если ответ пришёл без поиска — не записывайте его.

**2. Источники:** шаблон `data/templates/sources_template.csv` → файл `P2_sources.csv`. Одна строка = одна страница о компании.

| Столбец | Значения / пример |
|---|---|
| source_id | `SRC-P2-001`, `SRC-P2-002`… |
| entity_id | `svet_kz`, `centr_krasok` или новый конкурент: латиница, `a-z0-9_` (`prime_home`) |
| entity_level | `retailer` / `manufacturer` |
| url | `https://2gis.kz/almaty/firm/70000001043802009` |
| source_type | `map_directory` (2ГИС, Яндекс, Google Maps), `social`, `marketplace`, `retailer_site`, `manufacturer_site`, `review_q&a`, `media`, `other_web` |
| platform | `2gis`, `yandex_maps`, `google_maps`, `instagram`, `kaspi`… |
| city | `almaty` / `astana` / `karaganda` / `national` |
| ownership | `owned` (страница компании) / `third_party` / `unknown` |
| content_summary | что **реально** на странице: «адрес Кабдолова 1/8, категория "Люстры", 4.7★, 120 отзывов» |
| issues_found | расхождения: другой телефон, старый адрес, нет категории |
| cited_in_response_ids | ID ответов AI, где эта ссылка **была процитирована** (`OBS-P2-C04 \| OBS-P3-G04`). Не видели в ответах — пусто |
| observed_at | `2026-11-20T15:30+05:00` |
| verification_status | `pending` (проверит P3) |
| collector | `P2` |

**Правила источников**
- Не делать вывод о конкуренте по одному поисковому результату: конкурент — тот, кого назвал AI **или** кто подтверждён двумя независимыми источниками (сайт + 2ГИС).
- Присутствие источника ≠ цитирование AI. `cited_in_response_ids` — только наблюдённое.
- Только открытые страницы, без входа в чужие аккаунты, без массового скачивания.

**3. Каталог брендов:** `brand_catalog_template.csv` → `P2_brand_catalog.csv`. Пример **формата** (товар и URL выдуманы):
`BC-P2-001,maytoni,Maytoni,chandelier,svet_kz,Люстра Maytoni Ring MOD013PL-04W,MOD013PL-04W,https://svet.kz/...,2026-11-20T16:00+05:00,"В наличии: Алматы",pending,P2,`
`availability_note` — дословно с сайта. «Есть в каталоге» ≠ «есть на складе».

**4. Правки:** `proposals_template.csv` → `P2_proposals.csv`. В `after` — только факты, которые есть в `evidence`. `implementation_type` из словаря (`LOCAL_BUSINESS_PROFILE` для 2ГИС/Яндекса, `SOCIAL_CONTENT`, `CATEGORY_PAGE`…).

## C. Передача без Git

1. Google Sheets → **Файл → Скачать → CSV**. Из Excel: «Сохранить как → CSV UTF-8». Файлы с `;` тоже принимаются.
2. Назовите файл как шаблон: `P3_observations_gemini.csv`, `P2_observations_chatgpt_search.csv`, `P2_sources.csv`…
3. Отправьте капитану (P1) в Telegram **как файл** (скрепка → Файл), а не как фото. Скриншоты — тоже **файлами**, одной пачкой, имена `OBS-…png`.
4. Капитан загружает CSV в дашборд («Импорт наблюдений») и присылает в ответ таблицу ошибок или «принято». Исправлять нужно в своём Google Sheets, а не на ноутбуке капитана.
5. Каждый следующий раз отправляйте **файл целиком, с тем же именем** (старые строки + новые). Капитан нажмёт «Заменить предыдущую версию»; старая версия остаётся в истории Git.

## D. Проверка файла до импорта

- **Без Python:** у капитана в дашборде → «Импорт наблюдений» → выбрать файл. Ошибки показываются таблицей «строка · поле · причина», файл при этом **не сохраняется**.
- **С Python** (в папке проекта):
  ```zsh
  cd src
  ../.venv/bin/python -m geolab.contract observations ../data/raw/manual/P3_observations_gemini.csv
  ../.venv/bin/python -m geolab.contract sources ../data/research/P2_sources.csv
  ```
  Последняя строка `ошибок 0` = можно сдавать. Предупреждения (`WARNING`) не блокируют, но их надо прочитать.
- Частые ошибки: время без `+05:00`; время в будущем (часы на ноутбуке); запрос отличается от таблицы (перепечатан вручную); ссылка без `https://`; `verified` без `verified_by`.
